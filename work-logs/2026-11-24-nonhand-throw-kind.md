# 作業ログ 2026-11-24: 生成の手以外の投げに投げ方が付かない

- 日付: 2026-11-24
- 実施者: 手動（オーナー報告「生成時、手以外の投げにチェックが入っているが投げ方が未選択になる場合がある」）
- 対象issue: なし

## 調べたこと

- `autoThrowStyles` が全手具に投げ方の無い汎用の「手以外の投げ」（`id: "nonhand"`）を持っていた。スティックには 2026-11-23 に投げ方つきの「肩に引っ掛けて投げ」（`SHOULDER_HOOK_STYLE_ID`）を足したが、汎用のほうが残っていたので、それが選ばれるとエディタでは投げ方が未選択に見えた。
- スティックの手以外の投げの投げ方は「肩に引っ掛けて投げ」だけ（`NON_HAND_THROW_KINDS`）。汎用に投げ方を付ける案は、肩に引っ掛けて投げの頻度を倍にしてしまう（オーナーの「背面投げより少なく」に反する）ので採らなかった。

## やったこと

- `autoThrows.ts`：投げ方（`NON_HAND_THROW_KINDS`）がある手具では汎用の「手以外の投げ」を作らない（今はスティックだけ）。
- `shoulderHook.test.ts`：自動の投げ候補の手以外の投げは、スティックでは必ず投げ方つき（修正前のコードで落ちることを確認）。
- `autoThrows.test.ts`：手以外の投げをidではなくタグで見るように。`generate.test.ts`：「投げが続かない」は投げがタンブリングより2本以上多いと避けられないので、その場合は対象外にした（種7で 投げ5・タンブリング3 になった）。

## 確認

- `npm test`・`npm run test:slow`（1200件）成功。`npm run quality`：許容幅を超えて下がった指標なし（スティックだけ少し動いた）。
- 実測（スティック、上限 3.0／4.5／なし × 15構成）：手以外の投げ 6（すべて投げ方なし）→ 0。肩に引っ掛けて投げは候補には入るが、評価で選ばれていない。

## 気づき・申し送り

- 生成した構成にスティックの手以外の投げが出なくなった。肩に引っ掛けて投げをある程度出したいなら、評価か候補の確率（`SHOULDER_HOOK_LOW_CHANCE` など）を見直す必要がある（オーナー判断）。
