# 作業ログ 2026-10-01: 生成：採用される難度を1段以内に揃える

- 日付: 2026-10-01
- 実施者: 手動（オーナー依頼）
- 対象issue: なし（依頼「ランダム生成時、難度として採用されるシリーズの難度がばらつかないようにして／二つ以上乖離しないように。CとEが共存しない、B以下がない。技自体のばらつきはok。加点のための低難度の投げはそのまま残して」）

## 調べたこと

- 採用（重複でなく上位3つ）ユニットの難度を持つ配列は4つ：`seriesBreakdowns[].tumRows` /
  `handRows`（`.diff`）、`handElementRows` / `ropeJumpRows`（`.difficulty`）。どれも
  `adopted`/`inTop` を持つので、まとめて見れば「採点される6ユニット」が取れる
- 直す前の実測（手具 × 上限2.5/3.0/3.5、各25構成）：**12条件すべてで幅2以上が 25/25**。
  しかも幅3〜4が大半で、内訳は `ABDE` `ABCDE` のように A・B と E が同居していた
- 原因の切り分け（上限3.0・スティック25構成）：`requireAllElements: false` にすると
  幅2以上が 12/25 → **3/25**、D平均は 2.94 → 2.96 でほぼ同じ。
  → **必須要素を全部満たすことがばらつきを作っている**（オーナーの指摘どおり）
- 低いユニットの中身を出したら、ほぼ全部が**連続投げの安いほう**（投げ→1シェネ→キャッチ）。
  これは 多様な投げ受け の種類を操作を増やさずに1つ稼ぐ形（`leadPair` / `trailPair`）。
  投げ4回（うち1本が投げタン）だと徒手ユニットがちょうど3つ＝上位3つに全部入るので隠れられない
- 要求値と必須要素の関係も確認（スティック20構成）：満たした数は
  上限1.5 → 3.7/6、2.0 → 5.0、2.5 → 5.3、3.0以上 → 6.0/6。
  減ってはいるが `REQUIRE_ALL_ELEMENTS_MIN_SCORE`（3.0）で段差になる
- 要求値と加点の関係も確認：加点計は 0.15 / 0.25 / 0.30 / 0.33 / 0.37 / 0.55 / 0.68
  （上限1.5 / 2.0 / 2.5 / 3.0 / 3.5 / 4.5 / なし）。素直に減っていて問題なし

## 試して駄目だったこと（ここが本題）

1. **はみ出しに重みを掛けて評価から引く**。0.5 → 1.5 → 4 と上げても幅2以上は
   25/25 → 16〜22/25 で頭打ち。ばらつきは重みではなく**経路**の問題で、Dスコアの上限に
   張り付いた構成では「安い投げを厚くする」1手が上限を超えてしまう
2. 重みを 0.7 まで強くすると幅は縮むが（1〜11/25）、**貪欲法の他の釣り合いを壊した**：
   安い投げは1本やめれば消えるので上限3.0の投げ4回以上が 85% → 58%、投げとタンブリングの
   交互の並びも崩れ、難度の比重のつまみも効かなくなった（既存テスト5本が落ちた）。
   依頼は「加点のための低難度の投げはそのまま残して」なので逆方向
3. 幅（最大 − 最小）が減る手だけを採る詰め直し → ほぼ1手も見つからない。
   幅は最大と最小しか見ないので足場が無い
4. 自動生成の「量」を2か所同時に動かす詰め直し → 選ばれたシリーズの多くが量を変えられない
   （最小形は `cheneCountRange` が1通り）ので動かせなかった
5. 予算だけ増やす（0.6 → 1.2 → 2.0）→ 21 → 19 → 18 で頭打ちのうえDが 2.41 → 2.23 と落ちた
6. 詰め直しの途中で評価が −89 まで落ちていたのを発見（範囲外・投げタン超過などの ×100
   ペナルティは `rangePenalty` のチェックだけでは防げない）。予算の外に出ない形に直した
7. 「余地を作る」手（はみ出しは同じでDスコアだけ下げる）が暴走して下げ続けていたので、
   連続回数に頭を打たせた（`SPREAD_REPAIR_ROOM_RUN` 2。3・4にしても変わらない）

## 気づき・申し送り

- **完全には揃わないのは構造的**。上限いっぱいではDスコアが張り付くので、安いユニットを
  1段上げるには別のユニットを1段下げる必要があり、難度点の刻み（0.1/0.2/0.3/0.5/0.7）が
  合わないと動けない。残るのは「1ユニットが1段だけ外」がほとんど
- 残りの主因は **必須投げ をいちばん安く満たす最小形**（投げ→キャッチ ＝ A難度の徒手ユニット）。
  加点のための投げと同じ形なので、依頼どおり潰していない
- `REQUIRE_ALL_ELEMENTS_MIN_SCORE`（3.0）が段差なのが、上限3.0 がいちばん揃いにくい理由。
  要求値に応じて必須要素を**少しずつ**緩める（三宙 → つなぎ → …）形にすると
  2点台後半の構成がもっと素直になりそう。範囲外なので起票した: #126
