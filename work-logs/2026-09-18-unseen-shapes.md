  実践例がないので、日本トップレベルなら実施するかも？というような技の重みを実現したい」）
- 対象issue: なし

## 相談への回答

**貪欲法そのものは見直し不要**と判断した。

- 評価が1つの数なので、ルールを足すときに「その形は何点ぶん好ましくないか」だけ決めればよく、
  探索側を触らずに済んでいる（直前の3つの形も探索は無変更）
- 貪欲法の弱点（先に埋めた枠を見直さない）は修復パスで埋まっている
  （`upgradeTumblings` でタンブリングのE率 67%→100%、`swapIn`＋再構築で上限ぴったりの必須要素）
- 生成時間 ~0.37s のままで、探索法を替える理由になる未解決の失敗例が無い

**見直すべきは「頻度をどこで決めるか」**で、今回それをやった。

## やったこと

`src/scoring/unseenShapes.ts` を新設し、「実施例は無いが現実的な形」を1か所に宣言した。
形ごとに4つだけ書く：

| 宣言 | 意味 |
| --- | --- |
| `chance`（`UnseenChance`） | 候補に出す確率のカーブ（`base` / `riseFrom` / `risePerPoint` / `max`） |
| `earns` | その形が稼ぐ点数。評価はこれをそのまま打ち消す（＝点数的に中立） |
| `extra` | 中立化のうえで、さらに嫌うぶん |
| `count(series)` | 構成の中にその形がいくつあるか |

- 候補づくりは `unseenShapeChance(id, 要求値)` を呼ぶだけ（`autoThrows` / `autoTumblings`）
- 評価は `unseenPenalty(series)` を呼ぶだけ（`generateEvaluate`。`rareStyleCount` ×
  `RARE_STYLE_WEIGHT` を置き換え）
- `RARE_THROW_TUMBLING_*` / `rareThrowTumblingChance` / `rareStyleCount` /
  `RARE_STYLE_WEIGHT` は廃止（宣言に吸収）
- `NO_VIEW_TAG` は `autoThrows.ts` 直書きから `constants.ts` に移した
  （`unseenShapes` が `autoThrows` を import すると循環するため。`autoThrows` からは再輸出）

## 判断したこと

- **`earns` と `extra` を分けた。** 中立化（＝打ち消し）と「それでも嫌う」を混ぜると、
  なぜその値なのかが1年後に読めない。テストで
  「`earns` は0か技術加点ぶん」「合計は現実志向の重みの段（0.9以下）」を縛っている
- **投げタンの左手投げは `earns`＝0**。稼ぎが技術加点ではなく「手具別必須要素を満たす」側に
  あり、必須要素の重み（10）は打ち消せない。同じ必須要素を満たす普通の投げ受けが候補に必ずある
  ので比較では相殺される、という割り切りで `extra` だけを持たせた（挙動は従来と同じ0.1）
- カーブは3形とも既定（`UNSEEN_CHANCE_DEFAULT`）のまま。形ごとに変えられるようにはした

## 確認（挙動を変えていないことの証明）

要求値のカーブが3形とも同じなので `rand()` の消費順は変わらない。固定シードで前後比較した：

- 候補（4手具 × 要求値4通り × 12シード）：投げの `throwStyle/catchStyle/pattern` と
  タンブリングのシリーズ内容、および評価の減点額 → **575行すべて一致**
- 生成結果（4手具 × 要求値5通り × 10シード）：Dスコアと全シリーズの内容 → **200件すべて一致**

テスト：`autoThrows.test.ts` の稀な形のテストを**表から回す**形に書き換え（カーブ・
中立化の不変条件・数え方が重ならないこと）。`autoTumblings.test.ts` の閾値も
`unseenShape("throwTumBackCatch").chance.riseFrom` から読むようにした。
`npm test` **578 passed (15 files)**、`npm run build` 成功。
