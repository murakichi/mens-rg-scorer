- 同じ日に7本目

## 調べたこと

issue の指示どおり「**今どちらの定義が効いているか**」から確認した。

- 定義は `src/index.css:120`（ヘッダー用）と `src/index.css:1644`（ひねり入力用）の2箇所。
  **詳細度が同じ**（どちらも `.mode-btn`）なので、**後者が全面的に勝つ**。
- 実測（本番ビルドで `getComputedStyle`）:

  | ボタン | クラス | 変更前 |
  |---|---|---|
  | 個人モード（選択中） | `mode-active` | 13px / padding 6px 16px |
  | 団体モード（非選択） | `mode-btn` | **11px / padding 5px 9px** |
  | レーティング（非選択） | `mode-btn` | **11px / padding 5px 9px** |

  つまり**ヘッダーの非選択ボタンだけが、技ブロック用の小さい見た目になっていた**
  （選択中と並ぶと大きさが食い違う）。issue の「片方を直すともう片方の見た目も変わる」はこのこと。
- ほかに同種の衝突が無いか、CSS 全体でトップレベルの単独クラス定義を数えた → 8件が2回定義。
  中身を見たところ**すべて同じ要素への追記**（近接行、プロパティが補完的）で、
  `.mode-btn` のような「**別物どうしの衝突**」は他に無かった。
- 判断: **自力で片付く**（CSSとクラス名だけ。採点ロジックに触れない）。

## やったこと

- `src/components/SeriesCard.tsx:309` のクラスを `mode-btn` → **`twist-mode-btn`**。
- `src/index.css:1644` の定義をそちらへ移し、「ヘッダーのものとは別物」というコメントを添えた。
- `src/components/classNames.test.ts`（新規4件）: 名前が分かれていることを固定する回帰テスト。
  スタイルそのものは測れないので、**ヘッダーは `mode-btn` を使う / 技ブロックは使わない /
  どちらもトップレベルの定義は1つだけ**、を確かめる。

### 判断したこと

- **issue は「見た目を変えずに済むよう」と書いていたが、見た目は変わる（直る）方を選んだ。**
  現状維持＝「ヘッダーの非選択ボタンだけ小さい」という不具合の維持になるため。
  変更後は3つとも 13px / 6px 16px で揃い、技ブロックのひねり切替は 11px / 5px 9px のまま。
  前後のスクリーンショットで確認済み。**意図と違っていれば戻せるよう PR に明記した。**
