### 迷って決めたこと

- **印刷時の非表示は列挙せず `.page:has(.print-sheet) > *:not(.print-sheet)` の1ルールにした。**
  個別に `.io-wrap` `.action-bar` … と消していくと、UI が増えるたびに紙面へ漏れる。
  `:has()` で条件を付けているのは**団体モードを白紙にしないため** — 団体にはまだ紙面が無いので、
  ルール自体が効かず従来どおりの印刷結果になる（`:has()` 非対応ブラウザでも同じく従来どおりに退化する）。
- 団体モードは issue の「まずは個人から」に従って対象外。

## セルフレビュー（`/code-review high`）

3件の指摘。**全部が「紙の上で数字が合わない／名前が違う」という同じ性質のもの**で、すべて実際の問題だった。
紙は画面と違って前後の文脈を見に行けないので、この種の不整合は画面より重い。

1. **難度内訳の行ラベルを位置で採番していた** — `タンブリング${k+1}` / `投げ${k+1}` としていたため、
   ロープ跳びが「投げ1（ロープ跳び…）」、投げタンが「タンブリング1（投げタン1…）」になり、
   画面の採番ともずれていた。画面（`SeriesCard` の `DiffRowLine`、`src/components/SeriesCard.tsx:703`）は
   **固定の種別名**（`D：タンブリング難度点` / `D：徒手難度点`）を使っているので、そちらに揃えた。
2. **シリーズ別の `dPart` を合計Dの真下に並べていた** — `dPart` には連続投げ加点・手具操作加点が入るが、
   これらは演技に1回きり（`score.ts:426` と CLAUDE.md）なので**足し合わせるとDと合わない**し、
   様々な跳び加点は入っていない。列そのものをやめ、代わりに**合算できるD集計**を出した。
3. **必須要素しか載せておらず、A残点が減った理由が紙面から追えなかった** — 手具別必須要素と違反が
   抜けていた。ここで A減点 合計を足したら**明細 -1.0 に対して合計 -1.4** になり、2と同じ穴が出た
   （手具操作不足 -0.4 が抜けていた）。最終的に **画面の `ScoreSummary` と同じ9分類**を並べる形にして、
   明細が必ず合計と一致するようにした。あわせて、チェックリスト側からは金額を外して二重に読ませない。

結果として紙面は自己完結する: D 1.0+0.7+0.3=2.0、A 0.4+0.1+0.3+0.6=1.4（A残点8.6）、
E -0.6（E残点9.4）、合計 20.0。**この一致はE2Eで機械的に検証している**（明細を正規表現で拾って合計と突き合わせる）。

修正後: `npm test` 494件 green、`npm run build` green、E2E 個人21項目・団体3項目 PASS、PDF 2ページ。
