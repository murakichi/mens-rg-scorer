### 判断したこと

- **採点ごとの入力（E実施減点・違反・芸術の欠点）は履歴に入れない。** issue の「含めないほうが
  履歴が構成の変遷と対応してわかりやすい」に従った。
- **手具とロープ跳びは履歴に入れた。** issue は「対象は series」と書いていたが、手具を切り替えると
  その手具で入力できない内容が落ちる（`stripForApparatus`）ので、**シリーズだけ戻すと画面に出ない
  入力が残る** — CLAUDE.md が警告している「見えないのに点になる入力」そのものになる。
- **1操作＝1履歴にするのは「形の署名」で判定した。** 数値だけを潰した JSON を比べ、
  形が同じ（＝数値を変えただけ）かつ 800ms 以内なら直前の履歴に吸収する。
  数値入力は1キーごとに `onChange` が飛ぶので、これが無いと1文字＝1履歴になる。
  タイマーを使わないので、テストで時間を渡して検証できる。
- **入力欄の中では Ctrl+Z を奪わない。** 文字単位で戻せたほうがよいので、ブラウザ本来の取り消しに譲る。

## セルフレビュー（`/code-review high`）

4件。**全部が React 層**で、純粋関数に切り出したスタック操作のほうは指摘ゼロだった。
切り出した部分が正しくても、その周りで壊れるということ。

1. **`applying` フラグの判定順が逆だった（いちばん厄介）** — 「中身が同じなら何もしない」を
   先に書いていたため、**まとめ（coalesce）の結果 undo の戻り先が今と同じ JSON になる**ケースで
   フラグが立ったまま残り、**次の本物の編集が記録されない**（戻せなくなる）。
   順番の問題なので、判定自体を `observeChange` という純粋関数に出して**テストで順番を固定**した。
2. **モーダル中に Ctrl+Z が裏の構成を戻していた** — テンプレート編集中に裏の演技が黙って変わる。
   `.modal-overlay` があるときはキーを無視するようにした。
3. **プルダウン・チェックボックス・数値入力で Ctrl+Z が何も起きなかった** — 「入力欄ではブラウザ本来の
   取り消しに譲る」を INPUT/SELECT 全部に適用していたが、**これらには本来の取り消しが無い**。
   技を選んだ直後の Ctrl+Z が無反応という、いちばん使う場面で効かない状態だった。
   譲る相手を**文字を打つ欄だけ**（text系 INPUT / textarea / contentEditable）に限定した。
4. **読み込み・破棄のあとに構成だけ戻せてしまう** — これらはジュニア・違反・欠点まで差し替えるので、
   構成だけ戻すと「古い構成 × 読み込んだ適用規則」という**存在しなかった状態**になる。
   両方で `history.clear()` を呼び、読み込んだ内容を新しい出発点にした。
