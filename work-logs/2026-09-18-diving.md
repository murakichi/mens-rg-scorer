# 作業ログ 2026-09-18: ダイビングを技に追加した（宙返りの直後は1段格上げ）

- 日付: 2026-09-18
- 実施者: 手動（オーナーからの技の追加依頼）
- 対象issue: なし

## 依頼の内容

- **ダイビング**を技に追加する
- 後方系で**頭から着地する**技なので、あとに技は続かない
- **A難度**
- 特例：**宙返りの後に連続で実施したら格上げ**
- ランダム生成では生成しなくてよい

## 判断が要った点（オーナーに確認した）

1. **格上げ先の難度** → 「B（1段上）」
   - `JUNIOR_SKILL_DIFFICULTY` / `FUTURE_SKILL_DIFFICULTY` と違って**位置で変わる**ので、
     技idだけを引く `skillDifficulty` では表せない
2. **三宙（宙返りの連続）に数えるか** → 「常に宙返りとして数える」
   - きりもみ系（`saltoOnlyInChain`＝連続の中でだけ宙返り）とは別扱いになる

## やったこと

- `types.ts`: `Skill.noAuto`（自動生成では組み立てない。入力画面には出す）を追加
- `constants.ts`:
  - `SKILL_LIST` に `a_diving`（ダイビング、後方系、A難度、`isSalto: true`、`noAuto: true`）
  - `DIVING_SKILL_ID` / `DIVING_UPGRADED_DIFFICULTY`（"B"）
  - **`skillDifficultyAt(skillIds, i, junior, future)`** を新設。並びのなかでの**その位置の**難度を返す。
    ダイビングが宙返りの直後（`skillDef(prev)?.isSalto`）なら格上げ、それ以外は `skillDifficulty` と同じ。
    間にA難度技（ロンダート・バク転）が入ると「連続」ではないので格上げしない
- `analysis.ts`: `calcTumblingDifficulty` が id ではなく**位置**で難度を引くようにした
- `team.ts`: `calcChunkDifficulty` も同じ（団体でも同じ特例が効く）
- `tumblingChain.ts`: `CHAIN_END_SKILLS` にダイビングを追加（後に技を続けない）
- `tumblingTransitions.ts`: `usableSkills` が `noAuto` の技を落とす（自動生成の候補に入らない）

## 確認

- 難度：単発 A ／ ロンダート→ダイビング A（宙返りではないので格上げなし）／
  後方1回半ひねり→ダイビング **B**
- 連続の難度：`ロンダート→後方1回半ひねり(C)→ダイビング(B)` = **D**
  （格上げが無ければ C 止まり）
- 三宙：`ロンダート→後方伸身2回ひねり→後方1回半ひねり→ダイビング` で
  `maxSaltoChain` = 3、必須要素の三宙が `passed: true`
- 自動生成：遷移表の1本目にも次の技にも出ず、候補40シードで**0件**。
  入力画面の選択肢（`skillOptions`）には出る。徒手動作の選択肢（`MOTION_OPTIONS`）には出ない
- テスト：`analysis.test.ts` に4件（難度の特例／連続の難度／三宙／選択肢）、
  `transitions.test.ts` に1件（自動生成に出ない・後に続かない）

## 気づき・申し送り

- 難度が**位置で変わる**のは今のところこの技だけ。増えるようなら `skillDifficultyAt` を
  「特例の表」を引く形（`JUNIOR_SKILL_COMBOS` と同じ作り）にしたほうがよい。
- `leadsBackward("a_diving")` は true を返す（後方系・ひねり無しなので）。
  頭から着地するので「後ろ向きに立っている」わけではないが、後に技が続かない以上
  この値が使われる場面が無いのでそのままにした。
- `autoThrows.ts` の分割（オーナー指示）はまだ未着手。
