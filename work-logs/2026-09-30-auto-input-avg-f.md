- 対象issue: なし

## やったこと

- `autoInput.ts` の `effectiveScores`: 候補のための平均難度を計算するときだけ、内部で十年後モードのF（0.9）まで数える（`computeScore(…, {future: "F"})`）。画面の採点には影響しない。E（0.7）で頭打ちだと、F相当のユニット（D難度＋非A2つの宙返り、シェネ×5の徒手など）がEと区別できなかった。
- 閾値（0.3/0.5/0.7）は据え置き。

## 測定（クラブ、自動生成各20本、上位3ユニット平均）

- D1〜1.5 / 2〜2.5 / 3〜3.5 / 4〜4.5 / 5〜5.5: 0.38 / 0.62 / 0.73 / 0.76 / 0.76（Eで頭打ちのとき 0.36 / 0.55 / 0.65 / 0.69 / 0.70）。
- 上位3シリーズ（各シリーズの最大）の平均は上位3ユニットと同じ値。全シリーズ（各シリーズの最大）の平均は 0.36 / 0.52 / 0.57 / 0.63 / 0.72、シリーズの難度点合計の平均は 0.35 / 0.49 / 0.54 / 0.60 / 0.67。

## 追記: 上位3シリーズで判定

- 判定は「シリーズごとの最高の有効ユニット」の**上位3シリーズの平均**に変更（`effectiveScores` はシリーズごとに1つ、`averageDifficulty` が上位3つ、`AVERAGE_TOP_COUNT`）。低難度のシリーズが除かれる（上位3つに入らない）のは従来どおり。
- 連続投げの2回目の投げも、いったんそのシリーズの候補に入れる（低ければ最高に負けて数えられない）。以前の「投げ2以降は除外」は外した。
- 生成ルーティンでは上位3ユニットと上位3シリーズが同じ値だったので、閾値は据え置き。
