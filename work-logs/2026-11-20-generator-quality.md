# 2026-11-20 生成の質を測るテスト（`npm run quality`）

## 依頼
- 生成の質を測るテストを作る（乱数を1回足すだけで生成の質が揺れる問題への備え）。

## 変更
- `src/scoring/quality.ts`：場面（手具×上限3.0／4.5／なし／下限4.2）、指標（範囲内・D平均・A平均・必須充足・全部E・E不足・加点重複）、許容幅、基準値との比較（`qualityRegressions`）。
- `scripts/quality.mjs`（`npm run quality`）：表を出して基準値と並べ、許容幅を超えて下がった指標に ▼。`--update` で基準値を書き換え。
- `src/scoring/__tests__/quality-baseline.json`：基準値。
- テスト：`generateQuality.test.ts`（比べ方の正しさ、通常のテスト）と、`generateQuality.<手具>.test.ts`（基準値との比較、`slowIt`。手具ごとにファイルを分けて並列に走らせる。約2分）。

## 判断
- 「全部E」の割合だけでは揺れが大きく、全部Eを狙う重みを0にしても 72%→56%（25構成）で許容幅に収まった。揺れの小さい「E不足」（E未満の採点ユニット数の平均）を足し、下限4.2の場面は60構成にした。重みを0にすると ▼ が付くことを確かめた。
- 乱数を1回足しただけの版はクラブで E不足 +0.14（許容幅 0.15 の内）。揺れと本当の悪化はこの物差しでは見分けきれないので、許容幅は揺れの大きさに合わせた。小さな変化を見たいときは `-n` を増やして変更前後を比べる。
- 形ごとの出現割合（味付け）は指標に入れていない。それは個別の `slowIt` テストの役目。

## 残り
- ロープの A平均が7.9とほかの手具（8.5〜8.8）より低いのは、生成が跳びを作らないので跳びの手具別必須要素4つ（各0.3、計1.2）が引かれているため（1構成で確認）。基本徒手・手具操作の多様性の減点は全手具に共通で入っている（生成はA側の手入力を作らない）。
