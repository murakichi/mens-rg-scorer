# 作業ログ 2026-09-17: 転回系の多様性の減点を自動計算する

- 日付: 2026-09-17
- 実施者: 手動（オーナーの依頼）
- 対象issue: なし

## 調べたこと

- §3.5.6.4 の欠点テーブルは `ART_DEDUCTION_ITEMS`（手入力）で、`tumVariety` は上限0.50・減点幅 0.1/0.2。
- オーナーの基準：上級者が必須要素を満たす構成は 転回9〜11個（A難度込み）＝宙返り6〜8個。
  全部違う技なら減点なし、種類が減ったぶん減点。
- 実測でも生成構成の宙返りは上限なしで平均8.1個・7.7種類（`src/scoring/__tests__/zz-probe.test.ts` で計測、削除済み）。
  基準と合っていたので、`repeats = 実施数 − 種類数` × 0.1 をそのまま採用した。

## やったこと

- `src/scoring/analysis.ts`: `tumblingVariety(list, junior)` を追加（A難度の転回技と徒手動作は数えない）
- `src/scoring/constants.ts`: `TUM_VARIETY_ITEM_ID` / `TUM_VARIETY_DEDUCTION_STEP`（0.1）
- `src/scoring/score.ts`: `ScoreResult.tumVariety` として返す。**A減点には自動では入れない**
  （手入力の値だけがA減点に入る従来どおりの扱い）
- `src/components/IndividualScorer.tsx` / `src/index.css`: 項目の横に「自動計算」ボタン。
  押すと手入力欄に自動計算値が入る。注記に宙返りの個数・種類数も出す
- `src/scoring/generate.ts`: 評価で自動計算値をそのまま減点として負う
  （上級者ほど種類が増えて減点が小さくなる）

## 確認

- `npm test`: 514件パス
- `npm run build`: 成功
- 実測（20構成ずつ・stick）：減点の平均は 評価に入れる前 0.09/0.12/0.11/0.10/0.06（上限1.5/2.5/3.5/4.5/なし）
  → 入れた後 0.03/0.06/0.07/0.05/0.04。Dスコアの平均は変わらない

## 気づき・申し送り

- 既存テスト「同じ点数なら転宙を使わない構成を選ぶ」は、比較対象が前宙2連続＝多様性の減点0.1を負う形だった
  ので、前宙→側宙（減点0）に変えた。実施が少ない技の重み（0.02）より多様性の減点（0.1）が強いのは意図どおり。
- 前宙の繰り返しはこの減点では特別扱いしていない（生成側の好み `REPEATABLE_SALTOS` とは別物）。
  実際の審判が前宙の繰り返しを見逃すなら、`tumblingVariety` 側にも例外が必要。
