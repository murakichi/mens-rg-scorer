# 作業ログ 2026-10-14: 操作バーが携帯幅で横にはみ出す回帰を直した

- 日付: 2026-10-14
- 実施者: resolve-issue skill（#70 の作業中に見つけた自分の回帰）
- 対象issue: なし（**#68 で自分が入れた回帰**。issue は起こさず、その場で直した）
- 同じ日に3本目

## 調べたこと

- #70 の比較画面を携帯幅(390px)で確認していて、横スクロールが出ているのに気づいた。
  比較モーダルが原因かと思ったが、**モーダルを閉じた状態でも出ていた**。
- はみ出していたのは `.action-bar-btns`（画面下の sticky な操作バー）: 幅 312px に対し画面 390px、
  右端が 410px まで伸びて 20px はみ出す。
- **`origin/main` 単体でも同じ 20px のはみ出しを確認**（`git worktree` に出してビルドして実測）。
  つまり #70 の変更とは無関係で、**#68 で操作バーに「元に戻す」「やり直す」を足したときの回帰**。
- CLAUDE.md は「phones never scroll sideways」を設計の前提として明記している。これに反していた。
- `@media (max-width: 560px)` には「画面を塞がないよう1行に収める」という意図で
  `.action-bar { flex-wrap: nowrap }` が入っている（`src/index.css:1423`）。ボタンが4つになって収まらなくなった。

## やったこと

- 狭い画面では操作バーのボタンの**文字を落としてアイコンだけ**にした。
  - `IndividualScorer`: 「構成を保存」「テンプレート」のラベルを `<span className="btn-label">` で包み、
    `aria-label` / `title` を付けた（読み上げと吹き出しでは名前が残る）。
  - `src/index.css`: `@media (max-width: 560px)` に `.action-bar .btn-label { display: none }`。
- 「1行に収める」という既存の方針は変えていない（折り返してバーが分厚くなると画面を塞ぐため）。
  「元に戻す」「やり直す」はもともとアイコンだけなので、見た目も揃う。

## 確認

- `npm run build`: green。
- ブラウザE2E（`vite preview`）8項目 PASS: 360 / 390 / 560 / 900px の4つの幅で
  **横スクロールが出ない（はみ出し0px）**こと、かつ**操作バーに4つのボタンが残る**こと
  （文字を落としただけで機能を削っていない）。

## 気づき・申し送り

- **ボタンを足したときに携帯幅を見ていなかったのが原因。** #68 のE2Eは機能（戻る・やり直す）しか
  見ておらず、幅の確認を入れていなかった。以後、操作バー／ツールバーに要素を足す回は
  390px の横スクロールも見る。
- 同じ理由で、上部ツールバー（`.io-wrap`）はボタンが増え続けている（今は9個）。
  こちらは `flex-wrap: wrap` なので横には溢れないが、縦に伸びている。整理は別途。
