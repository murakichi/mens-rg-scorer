## 調べたこと

指摘は4件：

1. 珍しさ0のとき、投げタンでないタンブリングで**前方系から入る**形を減らしたい（D0〜1点台の初心者でしか見ない）
   → あとから「**前宙つなぎは中級者レベルで実施するかも。そこは残してほしい**」
2. **切り返しからの側宙**も少し珍しい寄り
3. つなぎの中に**ハーフ（後方の半ひねり）**を実施する場合、**前半の宙返り**で使うことのほうが多い
4. **三回前転**も珍しい寄りの技

まず実測した。最初の計測は**テンプレートの語彙で歪んでいた**：`generateRoutine` は
`usedSkillIds(ユーザーのテンプレート)` で自動生成の技を絞るので、転回技を含むテンプレートを3本置くと
自動生成が5技しか使えず、前方入りが7〜9割という嘘の数字が出た。
転回技を含まないテンプレート（投げ→シェネ→キャッチ）を1本だけ置くと `usedSkillIds` が空になり、
技の一覧すべてが使われる。これで測り直した数字が下の before。

前方入りの原因は `roundoffEntryWeight` の減衰（目標Dが上がるほど後方入りの優先が消える）。
この関数のコメントは「Dスコアが上がるほど前方系・側方系から直接入る形が増える」と書いてあり、
今回の指摘と**真逆**。減衰そのものは「低スコアでは組み方の幅が狭くロンダート入りがほぼ唯一」
という意味では正しいので残し、前方入りを抑えるのは別の重みにした。

  - `forwardEntryWeight`（`FORWARD_ENTRY_WEIGHT` 0.2 / `FORWARD_ENTRY_FREE_SCORE` 2.0 /
    `FORWARD_ENTRY_CONNECT_FREE_SCORE` 3.5）。つなぎの形だけ下げ始めを遅らせて「前宙つなぎ」を残す
  - `SWITCH_SIDE_SALTO_WEIGHT`（0.3）、`CONNECT_FINISH_HALF_WEIGHT`（0.3）、`isBackHalfTwistSalto`
  - `roundoffEntryWeight` のコメントを直した（役割の違いを明記）
- `tumblingTransitions.ts`
  - `first` の辺に前方入りの重み（`pattern.throwCatch` は対象外）
  - `next(prevId, beforePrevId?)` に**その前の技**を足し、切り返しからの側宙だけ下げる
  - `afterConnect` の辺でハーフを下げる（`basicLevel` は対象外）
- `autoTumblings.ts`: つなぎ技を含んだ並び `flow` を持ち、`next` に渡す。
  つなぎを挟むと向きが変わるので、そこを切り返しと読ませない
- `autoThrows.ts`: `VERTICAL_THREE_CHANCE`（0.25）/ `VERTICAL_THREE_FREE_SCORE`（4.5）/
  `verticalThreeChance`。**形ごとに1回**引く（投げ方ごとに引くと生き残りを貪欲法が拾う）

## 確認

実測（スティック、25構成ずつ。自動生成のタンブリングのみ）：

| | 前方入り（目標3.0/4.5/なし） | 切り返し側宙 | つなぎハーフ 前/後 |
| --- | --- | --- | --- |
| before 珍しさ50 | 30% / 28% / 32% | 7/17（上限なし） | 4/4・7/11 |
| after 珍しさ50 | **12% / 8% / 10%** | **3/20** | **7/0・6/2** |
| before 珍しさ0 | 14% / 22% / 22% | 10/31 | 7/11 |
| after 珍しさ0 | **14% / 0% / 6%** | **3/25** | **6/2** |

目標1.5点は前後で変わらず（初心者の形は残す）。
前転3回（60構成）：下限4.0点 11本 → **3本**、下限5.0点 6本 → 7本（免除どおり変わらず）、D平均は同じ。

## 気づき・申し送り

- **未対応**：上限3.0で生成した構成（オーナー提供）が「投げ3本＝最低限＋D難度の単発タンブリング2本」
  という最高効率の形になっている。原因は評価式で、`DIFFICULTY_PREFERENCE_WEIGHT`＋
  `TUMBLING_PREFERENCE_WEIGHT`（合計0.6／点）が `THROW_COUNT_UNDER_WEIGHT`（0.1／本）より
  はるかに重いので、Dの予算が決まっていると「投げを減らしてタンブリング難度に振る」のが
  常に得になる。`SKILL_MAX_DIFF_STEPS` が3.0でD難度を解禁しているのも効いている。
  これは重み1つの話ではないので別途。
- 計測時のテンプレート語彙の罠（`usedSkillIds`）は、今後の生成の実測すべてに効く。
  転回技を含まないテンプレート1本で測るのを既定にしたほうがよい。
